# Задание 3: Векторный индекс базы знаний

## Описание

Этот модуль преобразует подготовленную базу знаний в векторный индекс для семантического поиска релевантных фрагментов текста по пользовательским запросам.

## Используемые технологии

### Модель эмбеддингов

- **Название:** `sentence-transformers/all-MiniLM-L6-v2`
- **Репозиторий:** https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2
- **Размер эмбеддингов:** 384 измерения
- **Особенности:**
  - Быстрая и эффективная модель для семантического поиска
  - Хорошо работает с английским текстом
  - Оптимизирована для баланса между качеством и скоростью
  - Работает на CPU без необходимости GPU

### Векторная база данных

- **Технология:** ChromaDB
- **Обоснование выбора:**
  - Встроенная поддержка метаданных (источник, заголовок, позиция чанка)
  - Инкрементальные обновления (можно добавлять новые документы без полной переиндексации)
  - Простой API и интеграция с LangChain
  - Автоматическая персистентность (данные сохраняются на диск)
  - Производительность достаточна для текущего объёма данных

### Разбиение на чанки

- **Метод:** RecursiveCharacterTextSplitter из LangChain
- **Размер чанка:** 500 символов (~500 токенов)
- **Перекрытие:** 50 символов (для сохранения контекста между чанками)
- **Стратегия:** Рекурсивное разбиение по разделителям: `\n\n`, `\n`, `. `, ` `, ``

## Использование

### Построение индекса

Запустите основной скрипт:

```bash
python build_index.py
```

Скрипт выполнит следующие шаги:
1. Загрузит все текстовые файлы из `knowledge_base/`
2. Разобьёт документы на чанки с сохранением метаданных
3. Сгенерирует эмбеддинги для каждого чанка
4. Создаст векторный индекс в ChromaDB
5. Сохранит индекс в директорию `vector_index/`
6. Выполнит тестовые запросы для проверки качества

### Тестирование поиска

**Рекомендуется начать с:**

```bash
python usage_example.py
```

Этот скрипт показывает полный пайплайн работы с индексом, включая расширение запросов и восстановление терминов. Демонстрирует 5 практических примеров использования.

**Для интерактивного тестирования:**

```bash
python test_search.py
```

**Или используйте в коде:**

```python
from build_index import load_vectorstore, expand_query, restore_original_terms, load_terms_map

vectorstore = load_vectorstore("vector_index_backup")
terms_map = load_terms_map()

# Запрос пользователя
user_query = "ваш запрос"

# Расширяем запрос для поиска
expanded_query = expand_query(user_query, terms_map)

# Поиск
results = vectorstore.similarity_search_with_score(expanded_query, k=5)

# Восстанавливаем оригинальные термины в результатах
for doc, score in results:
    restored_content = restore_original_terms(doc.page_content, terms_map)
    print(restored_content)
```

## Метаданные чанков

Каждый чанк содержит следующие метаданные:

- `source`: Путь к исходному файлу (относительно `knowledge_base/`)
- `title`: Заголовок документа (первая строка файла)
- `filename`: Имя файла
- `chunk_id`: Уникальный идентификатор чанка в документе

Эти метаданные используются для:
- Цитирования источников в ответах бота
- Отслеживания происхождения информации
- Навигации к оригинальному документу

## Важно: Расширение запросов и восстановление терминов

**Проблема:** В базе знаний все термины были заменены (например, "Sharingan" → "Crimson Lens", "Naruto" → "Kael"). Если искать по оригинальным терминам, поиск не найдёт нужные документы. А найденные документы содержат заменённые термины, которые нужно вернуть к оригинальным для пользователя.

**Решение:** Реализован полный пайплайн с двумя этапами:

1. **Расширение запроса** (`expand_query()`): заменяет оригинальные термины на заменённые перед поиском
   - Запрос пользователя: `"What is Sharingan?"`
   - Расширенный запрос: `"What is Crimson Lens?"`
   - Поиск выполняется по расширенному запросу

2. **Восстановление терминов** (`restore_original_terms()`): возвращает заменённые термины к оригинальным в найденных документах
   - Найденный текст: `"Crimson Lens is used by Noctryn Line"`
   - Восстановленный текст: `"Sharingan is used by Uchiha Clan"`

**Полный пайплайн:**
1. Пользователь задаёт вопрос: `"What is Sharingan?"`
2. Расширяем запрос: `"What is Crimson Lens?"` (для поиска в базе)
3. Ищем в базе знаний → находим чанки про "Crimson Lens"
4. Восстанавливаем термины: "Crimson Lens" → "Sharingan", "Noctryn Line" → "Uchiha Clan"
5. Передаём в LLM: контекст с оригинальными терминами
6. Ответ пользователю: на языке оригинала

Это позволяет искать как по оригинальным терминам (Sharingan, Naruto, Konoha), так и по заменённым (Crimson Lens, Kael, Verdant Reach), при этом пользователь всегда получает ответы с оригинальными терминами.

- **Время построения индекса:** зависит от количества документов и размера текстов

- **Скорость поиска:** <100 мс для запросов по индексу среднего размера

## Дальнейшее использование

Созданный индекс можно использовать в RAG-пайплайне:

```python
from langchain_community.vectorstores import Chroma
from langchain_community.embeddings import HuggingFaceEmbeddings
from build_index import (
    load_vectorstore,
    expand_query,
    restore_original_terms,
    load_terms_map
)

# Загрузка индекса
vectorstore = load_vectorstore("vector_index_backup")

# Загрузка словаря замен терминов
terms_map = load_terms_map()

# Запрос пользователя (может содержать оригинальные термины)
user_query = "What is Sharingan?"

# 1. Расширение запроса (Sharingan → Crimson Lens)
expanded_query = expand_query(user_query, terms_map)

# 2. Поиск релевантных чанков
results = vectorstore.similarity_search_with_score(expanded_query, k=5)

# 3. Восстановление оригинальных терминов в результатах
context_chunks = []
for doc, score in results:
    # Восстанавливаем термины в тексте
    restored_content = restore_original_terms(doc.page_content, terms_map)

    context_chunks.append({
        "content": restored_content,  # С оригинальными терминами!
        "source": doc.metadata.get("source"),
        "title": doc.metadata.get("title"),
        "relevance": float(score)
    })

# Теперь context_chunks можно передать в LLM для генерации ответа
```

**Важно:** 
- Всегда используйте `expand_query()` перед поиском, чтобы обеспечить корректную работу с заменёнными терминами в базе знаний
- Всегда используйте `restore_original_terms()` для восстановления оригинальных терминов в найденных документах перед передачей пользователю или в LLM

## Примечания

- При первом запуске модель эмбеддингов будет загружена из Hugging Face (может занять время)
- Для ускорения на больших объёмах данных рекомендуется использовать GPU (измените `device="cpu"` на `device="cuda"` в `build_index.py`)
- Индекс можно обновлять инкрементально, добавляя новые документы без полной переиндексации
